# 구글 광고 세팅 — 젠제네틱스

## 0. 먼저 정정: 경쟁사 광고가 뜨는 이유

검색 화면에 `yourserene.kr`(컴포트 보아지유 앤 코큐텐) 광고가 뜬 것은 **우리가 구글
광고를 안 해서가 아닙니다.** 그쪽이 「젠제네틱스」를 키워드로 사고 있거나, 관련 검색어
타겟에 우리 브랜드 검색이 걸린 것입니다.

**우리가 광고를 시작해도 저 광고는 계속 뜹니다.** 구글은 남의 브랜드명을 *키워드로*
구매하는 것을 막지 않습니다. 우리가 얻는 것은 다른 것입니다.

- **최상단 광고 자리를 우리가 차지**한다 → 우리를 찾아온 사람이 경쟁사로 새는 것을 막는다
- 자기 브랜드명은 광고 관련성이 최고점이라 **클릭당 비용이 가장 낮다**
- 광고 확장(사이트링크)으로 **제품별 링크를 한 번에 노출**할 수 있다

이것이 브랜드 방어 광고이고, 경쟁사가 우리 이름에 붙고 있으니 하는 게 맞습니다.

### 상표권 신고 — 가능한 것과 불가능한 것

| | 가능? |
|---|---|
| 경쟁사가 「젠제네틱스」를 **키워드로 구매** | ❌ 구글이 막지 않음 |
| 경쟁사가 「젠제네틱스」를 **광고 문구에 표기** | ✅ 상표권자 신고로 제한 가능 |

현재 그 광고 문구에 「젠제네틱스」는 없습니다. 그래서 지금 당장 신고로 내릴 수는
없습니다. 다만 **상표 등록이 되어 있다면 구글에 상표권자 등록을 미리 해두는 것**이
좋습니다 — 나중에 누가 광고 문구에 쓰면 즉시 제한됩니다.

## 2. 캠페인 3개 구조

키워드 성격이 달라서 예산과 입찰을 따로 관리해야 합니다. 한 캠페인에 몰면
브랜드 검색(저렴)과 일반 검색(비쌈)이 예산을 서로 잡아먹습니다.

| 캠페인 | 목적 | 검색 의도 | 예상 CPC |
|---|---|---|---|
| **① 브랜드 방어** | 우리 이름 검색 사수 | 이미 우리를 아는 사람 | 가장 낮음 |
| **② 붓기** | 신규 수요 확보 | 붓기 해결책을 찾는 사람 | 중간~높음 |
| **③ 칼륨** | 성분 인지 수요 | 칼륨 영양제를 찾는 사람 | 중간 |

세 캠페인 모두 **위치: 대한민국 / 언어: 한국어 + 영어 / 입찰: 클릭수 최대화** 로 시작하고,
전환 데이터가 30건 이상 쌓이면 **전환수 최대화**로 바꿉니다.

> **언어를 「한국어」만 체크하면 안 됩니다.** 구글의 언어 타겟팅은 *검색어의 언어*가 아니라
> *사용자의 구글 인터페이스·브라우저 언어* 기준입니다. 크롬을 영문으로 쓰는 한국인
> (개발자·외국계 근무자·교포·맥 기본설정 영문)이 상당수인데, 한국어만 걸면 이 사람들이
> 「붓기」를 한글로 검색해도 우리 광고가 안 나갑니다. 한국어 + 영어 둘 다 체크하세요.
> 위치가 대한민국으로 묶여 있으니 해외 트래픽은 어차피 안 들어옵니다.

확장검색(따옴표 없음)으로 하면 엉뚱한 검색에 예산이 나갑니다.

**영문 키워드를 넣어야 하는 이유**

- 브랜드명을 영문으로 치는 사람이 실제로 있습니다 — 패키지·인스타 핸들·명함에 `Zengenetics`
  로 적혀 있으니 그걸 그대로 검색합니다.
- 브랜드 키워드는 CPC가 가장 싸서, 열 몇 개 더 넣는 비용이 거의 0입니다. 대신 경쟁사가
  우리 영문명을 선점하면 막을 방법이 없습니다. **비어 있는 칸을 남기지 않는 것**이 핵심입니다.
- 한/영 전환을 잊고 친 `wpswpspxlrtm` 같은 것도 이론상 가능하지만, 구글이 자동 교정해주고
  실검색량이 사실상 0이라 넣지 않아도 됩니다.

**반대로 ②붓기·③칼륨 캠페인에는 영문 키워드를 넣지 마세요.**
`potassium supplement` / `swelling` / `bloating` / `edema` 류는

- 랜딩페이지가 100% 한글이라 클릭해도 못 읽고 즉시 이탈 → 광고비만 소진
- 글로벌 경쟁(미국 보충제 브랜드)과 같은 입찰판이라 CPC가 국내 키워드보다 몇 배 비쌈
- 대한민국 위치 타겟 안에서 이 검색을 하는 사람 = 주한 외국인 정도로 모집단이 극소

전환 추적이 없으면 "클릭 몇 번"만 보이고 "몇 개 팔렸는지"를 모릅니다. 그러면
입찰 최적화가 불가능합니다. **광고 켜기 전에 이것부터 하세요.**

### 5-0. 먼저 — gtag를 설치하지 마세요 (2026-09-22 확인)

GA4 속성 `498152534`(젠제네틱스_속성)를 직접 조회한 결과, **2026-09-09부터 구매 전환이
매출 금액까지 정상 수집되고 있습니다.**

| 날짜 | 거래수 | 매출(KRW) | 세션 |
|---|---|---|---|
| ~09-08 | 0 | 0 | 1,300~4,700 |
| 09-09 | 19 | 774,700 | 1,007 |
| 09-12 | 24 | 2,094,824 | 1,597 |
| 09-15 | 25 | 2,984,991 | 1,304 |
| 09-20 | 19 | 2,062,900 | 1,251 |
| 09-21 | 5 | 182,560 | 753 |

`핵심 이벤트(conversions)` 수가 `거래수(transactions)`와 매일 정확히 일치합니다 →
`purchase` 이벤트가 **이미 GA4 핵심 이벤트로 지정되어 있습니다.**

따라서 아래 5-2의 카페24 gtag 설치는 **하지 않습니다.** 대신 GA4 전환을 구글애드로
가져옵니다(5-1B). 이유:

| | GA4 전환 가져오기 ← 채택 | gtag 직접 설치 |
|---|---|---|
| 카페24 코드 작업 | 없음 | Head + 주문완료 페이지 |
| 에딧봇 삭제 위험 | 없음 | 있음 (실제로 겪음) |
| 주문금액(ROAS) | 이미 수집됨 | 변수명 직접 확인 필요 |
| 중복 제거 | 이미 됨 | transaction_id 수동 |

**GA4 가져오기의 한계 (알고 쓸 것)**: 데이터 지연 최대 24~48시간 / 향상된 전환
(Enhanced Conversions) 사용 불가 / GA4 어트리뷰션 적용. 월 광고비가 커지면 그때
gtag를 추가하고 기본 목표를 바꿉니다.

### 5-1A. GA4 ↔ 구글애드 연결 (완료: 2026-09-22)

구글애드 → 도구 → 데이터 관리자 → Google 애널리틱스(GA4) → 연결 → `젠제네틱스_속성`

상태: **연결됨**. 단 구글 안내에 따라 **링크 데이터가 반영되기까지 최대 24시간** 걸립니다.
그 전에는 5-1B의 가져올 전환 목록이 비어 있을 수 있습니다.

### 5-1B. 전환 가져오기

구글애드 → 좌측 **목표 → 전환 → 요약** → `+ 새 전환 액션` →
**「웹사이트」가 아니라 「가져오기」** → **Google 애널리틱스 4 속성** → **웹** →
`purchase` 체크 → 가져오기 및 계속하기

가져온 뒤 설정:

| 설정 | 값 |
|---|---|
| 목표 | 구매 |
| 전환 값 | GA4에서 가져온 값 사용 |
| 횟수 | 전체 |
| 전환 추적 기간 | 30일 |
| **기본 목표(Primary)** | **예** — 부차적 목표면 자동입찰이 무시함 |

### 5-1D. 완료 기록 (2026-09-22)

전환 액션 **1개** 생성 완료: `젠제네틱스_속성 (web) purchase` / 목표 `구매` / `기본(Primary)`

구글이 같이 추천한 3개는 **수락하지 않음**:

| 추천 | 거부 이유 |
|---|---|
| `…생애-첫-구매` 로 시작하는 페이지 방문 | 상품 페이지 방문자 전원이 "구매"로 집계됨 |
| `zg_purchase_repeat_view` | 조회 이벤트. 구매 아님 |
| `zg_purchase_unreadable` | 진단용 이벤트 (9/8에만 3건, 이후 0건) |

`add_to_cart` / `begin_checkout` / `view_cart` / `zg_buy_click` 도 전환으로 잡지 않음 —
전환 수가 뻥튀기되고 자동입찰이 구매하지 않는 사용자를 학습함. 필요하면 나중에
**부차적 목표**(관찰 전용, 입찰 미사용)로 추가.

**gclid 유실 검증 (2026-09-22)**: 광고 랜딩 3개 URL을 데스크톱/모바일 UA로 각각
테스트 → 전부 `200`, 리다이렉트 `0회`, `gclid` 최종 URL에 보존. 어트리뷰션 문제 없음.

```
/                                   → 200, 0 redirects, gclid 유지
/product/detail.html?product_no=11  → 200, 0 redirects, gclid 유지
/product/…포타슘-칼륨-20ea/11/        → 200, 0 redirects, gclid 유지
```

- 태그 설정에서 **전환 ID**와 **전환 라벨**을 받아두세요

### 5-2. (보류) 카페24에 태그 설치 — GA4 가져오기를 쓰므로 현재 실행하지 않음

카페24 관리자 → **디자인(쇼핑몰 디자인) → 코드 직접입력 → Head 영역**

> **중요**: 상품 상세설명이 아니라 **코드 직접입력**에 넣어야 합니다. 상세설명에 넣은
> `<script>`는 위지윅 편집기로 저장할 때 삭제됩니다(우리가 실제로 겪었습니다).
> 코드 직접입력은 카페24 자체 스크립트가 들어가는 곳이라 안전합니다.

**Head 영역에 넣을 코드** (`AW-XXXXXXXXX`를 본인 전환 ID로 바꾸세요):

```html
<script async src="https://www.googletagmanager.com/gtag/js?id=AW-XXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'AW-XXXXXXXXX');
</script>
```

**주문완료 페이지에 넣을 코드** — 카페24 관리자에서 주문완료 페이지 스크립트 위치를
찾아 넣습니다. 카페24는 주문완료 시 주문번호·결제금액 변수를 제공합니다.

```html
<script>
  gtag('event', 'conversion', {
    'send_to': 'AW-XXXXXXXXX/전환라벨',
    'value': 주문금액변수,
    'currency': 'KRW',
    'transaction_id': '주문번호변수'
  });
</script>
```

> 카페24 스킨 버전에 따라 주문완료 페이지 변수명이 다릅니다. 관리자에
> **마케팅 → 광고 → 구글 광고(Google Ads) 설정** 메뉴가 있으면 그걸 쓰는 게
> 훨씬 간단합니다 — 전환 ID/라벨만 입력하면 카페24가 알아서 심어줍니다.
> 그 메뉴가 있는지 먼저 확인해보세요.

### 5-3. 같이 고칠 것 — 깨진 인증 태그

같은 Head 영역에 이 줄이 있습니다.

```html
<meta name="google-site-verification=L-2Piu7-1q3VbB_MGlckHDXfk80m3D-pMCaa1qNn3c4" />
```

`name` 속성 안에 토큰이 들어간 잘못된 형태입니다. 올바른 형태는 이것입니다.

```html
<meta name="google-site-verification" content="L-2Piu7-1q3VbB_MGlckHDXfk80m3D-pMCaa1qNn3c4" />
```

바로 아래 네이버 태그(`name="naver-site-verification" content="..."`)와 비교하면
차이가 보입니다. 지금 Search Console 인증은 다른 방법으로 되어 있어 급하지는 않지만,
어차피 그 화면에 들어가시니 같이 고치세요.
